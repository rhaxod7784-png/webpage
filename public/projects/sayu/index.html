01 / ORIGIN

긴 토론은 어디에 남을까?

한 달에 한 번 만나는 토론 모임에서 몇 시간씩 이야기를 나누다 보면, 참여했던 사람조차 내용을 전부 기억하기 어렵습니다. 참석하지 못한 사람에게는 그날의 논의가 더욱 멀어집니다.

처음 떠올린 것은 녹음과 전사, 요약을 한곳에 모으는 도구였습니다. 그날의 생각이 녹음 파일 속에만 묻혀 있지 않고 나중에 다시 꺼내 볼 수 있었으면 했습니다. 거대한 공개 플랫폼이 아니라 실제로 제가 속한 모임의 필요에서 시작했습니다.

02 / SCOPE

누가 보고, 누가 원본을 들을 수 있을까?

대상은 사전에 승인한 약 10명의 회원입니다. 날짜를 선택해 Markdown 기록을 만들고 조회하며, 토론 중에는 녹음하고 이후 전사와 요약을 이용하는 흐름을 설계했습니다.

일반 회원의 기록 작성과 운영진의 녹음 원본 접근 권한을 분리했습니다. 모임의 목소리와 대화는 개인 정보이기 때문에, 공개 게시판처럼 노출하는 것은 처음부터 의도한 방향이 아니었습니다.

03 / ARCHITECTURE

말을 데이터로 다룰 때 생기는 문제

Cloudflare Workers에서 FastAPI를 사용하고, D1에는 회원과 날짜별 기록, 녹음 상태 등 구조화 데이터를 저장하는 방식으로 설계했습니다. 원본 오디오는 비공개 R2에 보관하고 Google 로그인과 접근 승인 목록으로 회원을 구분합니다.

녹음 구간 저장, Whisper 기반 전사, LLM 요약 기능을 연결하는 코드를 개발했습니다. 별도의 음성 분석 환경과 Modal을 검토한 기록도 있습니다. 개발 기록에는 음성 파일 읽기와 중단된 녹음의 복구를 개선하려는 커밋도 있습니다.

04 / VERIFICATION

코드가 있다고 실전에서 되는 것은 아닙니다.

브라우저의 녹음 기능은 화면 꺼짐, 백그라운드 제한, 네트워크 중단 등에 영향을 받을 수 있습니다. 몇 초짜리 구간이 저장됐다는 사실은 두세 시간의 토론이 안정적으로 녹음된다는 보장이 아닙니다.

자동 화자 식별과 장시간 실제 사용 조건의 전체 검증 등은 아직 완료로 제시할 수 없습니다. 이 서비스는 개발·검증 진행 중이며, 실제 모임의 목소리와 개인 기록은 포트폴리오에 공개하지 않습니다.

이 프로젝트의 핵심 배움은 기능 구현 못지않게 저장, 접근 권한, 중단 상황, 동의와 보관 기간을 함께 설계해야 한다는 점입니다.
